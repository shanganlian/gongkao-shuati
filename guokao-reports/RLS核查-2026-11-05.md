## 4. 权威核查 SQL（复制到 Supabase → SQL Editor 执行）

### 4.1 全库 enabled/disabled 清单（disabled 排最前）

```sql
select n.nspname                                                     as schema,
       c.relname                                                     as table_name,
       case when c.relrowsecurity then 'enabled' else 'DISABLED' end as rls,
       c.relforcerowsecurity                                         as rls_forced,
       (select count(*) from pg_policy p where p.polrelid = c.oid)   as policy_count
  from pg_class c
  join pg_namespace n on n.oid = c.relnamespace
 where c.relkind in ('r', 'p')                       -- 普通表 + 分区表
   and n.nspname not in ('pg_catalog', 'information_schema',
                         'pg_toast', 'extensions')
 order by c.relrowsecurity, n.nspname, c.relname;    -- DISABLED 在最上面
```

判读：`auth.*` / `storage.*` / `realtime.*` 是 Supabase 托管的系统表，正常为 enabled，不必动；真正要看的是 **`public.*`**（PostgREST 默认暴露的 schema）。

### 4.2 只看 disabled（期望 0 行）

```sql
select n.nspname || '.' || c.relname as table_name
  from pg_class c
  join pg_namespace n on n.oid = c.relnamespace
 where c.relkind in ('r', 'p')
   and not c.relrowsecurity
   and n.nspname not in ('pg_catalog', 'information_schema', 'pg_toast', 'extensions')
 order by 1;
```

### 4.3 附加风险：有 RLS 但一条策略都没有（= 客户端全锁死，易被误判成"接口坏了"）

```sql
select n.nspname || '.' || c.relname as table_name
  from pg_class c
  join pg_namespace n on n.oid = c.relnamespace
 where n.nspname = 'public'
   and c.relkind = 'r'
   and c.relrowsecurity
   and not exists (select 1 from pg_policy p where p.polrelid = c.oid)
 order by 1;
```

### 4.4 附表：anon 的表级权限（RLS 之外的第二道闸）

```sql
select table_name,
       string_agg(privilege_type, ', ' order by privilege_type) as anon_privs
  from information_schema.role_table_grants
 where grantee = 'anon' and table_schema = 'public'
 group by table_name
 order by table_name;
```

### A.8.1 兜底：方案 ② 的「单条 SQL 一次出全」（不想给连接串就用这个）

把下面**整段**粘进 SQL Editor，只返回**一行 JSON**，把这一行原样贴回即可：

```sql
with t as (
  select n.nspname as schema, c.relname as name,
         c.relrowsecurity as rls, c.relforcerowsecurity as forced,
         (select count(*) from pg_policy p where p.polrelid = c.oid) as policies
    from pg_class c
    join pg_namespace n on n.oid = c.relnamespace
   where c.relkind in ('r', 'p')
     and n.nspname not in ('pg_catalog', 'information_schema', 'pg_toast', 'extensions')
)
select jsonb_pretty(jsonb_build_object(
  'answer_records_exists', to_regclass('public.answer_records')::text,
  'tables_total',  (select count(*) from t),
  'disabled',      (select coalesce(jsonb_agg(schema || '.' || name order by schema, name), '[]'::jsonb) from t where not rls),
  'zero_policy',   (select coalesce(jsonb_agg(schema || '.' || name order by schema, name), '[]'::jsonb) from t where rls and policies = 0),
  'public_tables', (select jsonb_agg(jsonb_build_object('name', name, 'rls', rls, 'forced', forced, 'policies', policies) order by name) from t where schema = 'public'),
  'other_schemas', (select jsonb_agg(distinct schema) from t where schema <> 'public')
));
```

判读口径：`disabled` 应为 `[]`；`zero_policy` 里的每张表按 A.4 对应行处置；`answer_records_exists` 为 `null` 即该表在该项目**从未创建**（`create_answer_records.sql` 未执行）。
