## 2. 实现机制

### 2.1 Tailwind v4 变体（`src/index.css`）

```css
@custom-variant dark (&:where([data-theme='dark'], [data-theme='dark'] *));
```

- `ThemeToggle` 把主题写在 `<html data-theme="dark|light">`，该选择器让所有 `dark:` 工具类只在深色下生效。
- 浅色下 `data-theme="light"`，**没有任何 `dark:` 规则命中**，视觉效果与改造前一致。
- 已用构建产物验证层叠顺序（`@custom-variant` 生成 `:where()` 使特异性为 0，靠顺序覆盖）：

| 基础类位置 | dark 变体位置 | 结果 |
| --- | --- | --- |
| `.bg-white` @39012 | `.dark\:bg-slate-900:where(...)` @88319 | 通过（dark 在后） |
| `.hover\:bg-slate-800:hover` @68214 | `.dark\:hover\:bg-slate-600:where(...)` @95831 | 通过 |
| `.text-slate-900` @55400 | `.dark\:text-slate-100:where(...)` @92658 | 通过 |

## 4. 需求 ④ 的说明（请你确认）

- **localStorage 持久化未被改动**：仍是 `localStorage['bideti-theme']`，仍由 `ThemeToggle` 写入，读取顺序仍为 `html[data-theme]` → `localStorage` → `prefers-color-scheme` → 浅色。
- **防白闪脚本：原仓库 `index.html` 里并不存在**（上一轮排查结论：该文件仅 20 行、无任何内联脚本）。深色下若没有它，刷新会先闪一帧白底，因此本次在 `<head>` 补了一段等价脚本，只做一件事：首帧前按 `bideti-theme` / 系统偏好写 `document.documentElement.dataset.theme`。

```html
<script>
  (function () {
    try {
      var saved = localStorage.getItem('bideti-theme');
      var theme = saved === 'dark' || saved === 'light'
        ? saved
        : (window.matchMedia && window.matchMedia('(prefers-color-scheme: dark)').matches ? 'dark' : 'light');
      document.documentElement.dataset.theme = theme;
    } catch (e) {
      document.documentElement.dataset.theme = 'light';
    }
  })();
</script>
```

- 若你坚持 `index.html` 一行不动，删掉这 14 行即可：功能不受影响，唯一代价是深色模式刷新会白闪一帧。

## 6. 已知限制

1. `brand-gold` / `brand-ink` 品牌色未做深色重映射（金底墨字两色下均达标，改动会破坏品牌识别）。
2. `text-slate-400` 若直接落在 `slate-700` 上约 4.04:1，略低于文字标准；实际代码中 `slate-700` 只作实心按钮/状态胶囊底色，其上文字均为 `slate-100/200`（≥8.4:1），未出现该组合。
3. 面试舞台、语音播放器等原本就是深色面板（`bg-slate-950` / `bg-slate-900`）的区域保持原深色，不额外提亮，避免失去“舞台感”。
4. `public/` 下题目 JSON、图片、字体不含颜色，未改动。
