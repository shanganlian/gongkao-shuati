# 03 · 阿里云短信：个人主体的现实限制 + 两条可行路线

> 目标：加「手机号验证码登录」，签名 `必得题库`，模板 `您的验证码为${code}`。
> **先看结论再提交**：阿里云已对国内短信签名实施「资质实名」要求，
> 官方《使用须知》明确：*只有具备**企业资质**的用户才能提交签名并发送短信；无法提供企业资质的个人用户，可使用「短信认证服务」。*
> 也就是说，**个人实名的阿里云账号，大概率申请不到自定义签名「必得题库」**，需要换路线。下面是两条能走通的路。

## 1. 官方口径（原文要点，摘自阿里云短信服务《使用须知》《选型指南》）

| 维度 | 短信服务（SMS，可自定义签名） | 短信认证服务（PNVS 子服务） |
| --- | --- | --- |
| 自定义签名/模板 | 可以，**但需自行申请 + 运营商实名报备** | **平台预置，无法自定义，无需申请** |
| 签名申请主体 | 需企业资质（个人可凭**第三方企业资质 + 授权书**申请） | 不涉及签名申请 |
| 国内验证码短信 | 支持（个人需提供第三方企业资质） | 支持（5 类预置模板：登录/注册、修改绑定手机号、重置密码、绑定新手机号、验证绑定手机号） |
| 接入周期 | 签名+模板+实名报备，**全流程约 10–15 个工作日**（报备 7–10 天或更长） | **对接 API 当天可用** |
| 审核时长 | 签名/模板通常 **2 小时内**（9:00–19:00 周一至周日）；资质审核约 **2 个工作日** | 无需审核 |
| 计费 | 验证码/通知 **0.045 元/条起** | **0.06 元/次起**（核验免费） |
| 个人申请频次 | **1 个签名 / 日历日** | — |

> 结论：**周末去提「签名 必得题库 + 模板 ${code}」这条，在你个人实名账号下大概率被驳回**，
> 驳回理由通常是「签名归属资质不符 / 需提供企业资质或授权函」。别急着重提，先选路线。

## 2. 路线 A（推荐，能立刻上线）：短信认证服务

适合「只想要验证码登录」的场景，免签名、免模板、当天可发。

1. 阿里云控制台搜 **号码认证服务**（PNVS）→ 开通 **短信认证服务**；
2. 创建 AccessKey（RAM 用户，只授 `dypns:SendSmsVerifyCode`、`dypns:CheckSmsVerifyCode`）；
3. 调用 `SendSmsVerifyCode`：手机号 + 模板类型（登录/注册）+ 有效期，平台自动生成并下发验证码；
4. 调用 `CheckSmsVerifyCode` 校验（核验免费），校验通过后再给用户签发 Supabase 会话；
5. 计费 0.06 元/次起，先充 50 元试跑足够。

**优点**：今天就能用，不用等报备；平台托管防刷与核验逻辑。
**缺点**：短信里是**平台预置签名**（不是「必得题库」），文案固定为 5 类之一；不能发通知/推广类。

## 3. 路线 B：一定要「必得题库」签名（需企业资质）

任选其一满足资质：

| 方式 | 说明 | 现实难度 |
| --- | --- | --- |
| B1 主体升级为企业/个体工商户 | 阿里云账号实名改成企业（个体工商户营业执照通常可走企业认证，以实名页为准），之后用「已备案网站」作为签名来源 | 中（要办执照，1–3 天） |
| B2 借用第三方企业资质 + 授权书 | 官方允许：个人账号可用他人企业资质申请签名，需该企业出具**授权函** | 中（要找到愿意授权的企业，且签名须与该企业业务相关） |
| B3 个人硬提 | 部分老账号/特定类目仍能提交，但通过率低，且审核意见会要求补资质 | 高（不推荐作为唯一方案） |

若走 B，提交前准备（**材料清单**）：

- [ ] 企业营业执照彩色扫描件（B1/B2）
- [ ] 法定代表人身份证正反面（B1/B2）
- [ ] 授权函（B2，盖公章，写明授权个人账号申请并使用某签名）
- [ ] 备案截图：`https://beian.miit.gov.cn` 查询结果（含主办单位、网站名称、备案号、域名）
- [ ] 网站首页截图（PC + 移动端），能看清「必得题库」站名与业务内容
- [ ] 短信使用场景说明（一句话）：**「用户注册/登录时下发 6 位数字验证码，验证手机号归属」**
- [ ] 签名文案：`必得题库`（4 字，符合 2–12 字要求）
- [ ] 模板文案：`您的验证码为${code}，5 分钟内有效，请勿泄露于他人。`（验证码类，变量必须为数字）

## 4. 签名与模板的审核要点（个人/企业都适用）

**签名 `必得题库`**
- 2–12 个字，不含空格、不含 `【】`（系统自动加括号）、不含 URL/QQ/微信号/电话号码；
- 不得含「官方」「中国」「国家」「政府」「银行」「认证」等敏感或权威暗示词；
- 语义须与**备案网站名称**或**营业执照名称/商标**强相关（「必得题库」最好与站名完全一致）；
- 签名来源选择要与材料匹配：有商标选「商标」，有备案网站选「已备案网站」，别乱选；
- 个人账号 **1 个签名/天**，被驳回当天不能改完立刻重提，**一次填对最重要**。

**模板 `您的验证码为${code}`**
- 验证码类模板**必须**包含 `${code}`，且该变量只能是数字；
- 变量个数有上限（验证码类一般只允许 `code` 一个业务变量），别加 `${name}` 之类；
- 建议补一句有效期与安全提示（`5 分钟内有效，请勿泄露于他人`），比裸模板更容易过审；
- 不得含推广语、外链、联系方式、`回复TD退订`（验证码类不需要退订语）；
- 模板与签名要「同主体、同场景」，一个模板只能绑一个签名使用场景。

## 5. 费用与限额

- 短信服务：验证码/通知 0.045 元/条起（阶梯下降），套餐包 0.047 元/条起、有效期 24 个月；**运营商回执失败不计费**；
- 短信认证服务：0.06 元/次起（1000 次以内档），核验免费，套餐包 0.045 元/条起、有效期 12 个月；
- 两个产品的套餐包**不互通**，买错只能按各自规则退款（短信服务可自助退，认证服务要提工单）；
- 触发频控/超限的报错要在前端做「稍后再试」提示，别暴露内部错误码。

## 6. 代码侧接入方案（等你拿到资质再做，先记账）

- 服务端新增（`server.ts` 与 `netlify/functions/api.ts` 双端，逻辑放 `shared/`）：
  - `POST /api/auth/sms/send`：手机号 → 限频（同号 60s、同 IP 每小时 N 次、每日上限）→ 调 `SendSmsVerifyCode` / `dysmsapi`；
  - `POST /api/auth/sms/verify`：手机号 + 码 → 校验 → 用 `service_role` 建/查用户 → 签发会话或一次性 exchange token；
- 密钥：`/etc/bideti/bideti.env` 增 `ALIYUN_ACCESS_KEY_ID` / `ALIYUN_ACCESS_KEY_SECRET` / `SMS_SIGN_NAME` / `SMS_TEMPLATE_CODE`，`.env.example` 只留占位符；
- 前端：`AuthModal` 增加「手机号」tab（与现有邮箱验证码同构：发送 → 60s 冷却 → 6 位码），错误文案走 `src/lib/authErrors.ts`；
- 防刷必须做：图形/滑块验证码、同号 60 秒冷却、同号每日 10 次、同 IP 每小时 20 次、失败 5 次锁定 15 分钟。

## 7. 周末行动建议

1. **今天**：先跑路线 A（开通号码认证服务 + 建 AccessKey），拿到「当天可用」的验证码能力，登录体验立刻补上手机号；
2. **周末**：把路线 B 的材料（营业执照/授权函）确认清楚——**如果暂时没有企业资质，就不要提交签名申请**，避免被驳回占掉当日次数；
3. 无论走哪条，先把 §3 的备案截图、首页截图、场景说明准备好，后面换路线也不用重拍。
