# 02 · QQ 互联（connect.qq.com）个人开发者申请指南

> 目标：在 `igoiget.com` 登录弹窗里加一个「QQ 登录」，减少注册流失。
> 结论：**个人开发者可以申请「网站应用」并拿到 QQ 登录能力**，但硬门槛是
> 「网站已 ICP 备案 + 回调域名与备案域名一致 + 站点有真实内容且展示备案号」。
> 我们已满足后两条的一半（见 §1 现状核对），缺口是《用户协议》《隐私政策》独立页。

## 1. 现状核对（提交前先看一眼）

| 要求 | 我们的情况 | 结论 |
| --- | --- | --- |
| 已备案域名 | `igoiget.com`，宁ICP备2026004293号 | ✅ |
| HTTPS 可访问 | certbot 已签，`www` 与裸域都通 | ✅ |
| 页脚展示备案号 | `SiteFooter.tsx` 已展示并链接工信部 | ✅ |
| 站点有实质内容 | 题库、面试大厅、报名等 | ✅ |
| 独立《用户协议》URL | 当前只有 `SiteFooter` 弹窗占位 | ⚠️ 建议补 |
| 独立《隐私政策》URL | 同上 | ⚠️ 建议补 |

> 建议周末前把协议做成 `https://igoiget.com/agreement`、`/privacy` 两个可访问页（SPA 路由或静态页都行），
> 审核和后续 QQ/微信/短信申请都会复用。

## 2. 全流程（4 步）

| 步骤 | 入口 | 产出 | 参考时长 |
| --- | --- | --- | --- |
| ① 注册 + 个人开发者认证 | `https://connect.qq.com` 右上角「登录」 | 开发者账号通过审核 | 1–3 个工作日 |
| ② 创建网站应用 | `https://connect.qq.com/manage.html#/` → 创建应用 | 拿到 `appid` / `appkey` | 与 ① 同批 |
| ③ 应用审核 | 同上，提交后等通知 | 应用「已通过」，接口权限开通 | 通常 1–3 个工作日（以平台为准） |
| ④ 联调 | 本地/线上 | 能走通授权码换 token | 半天 |

## 3. 注册与个人实名

1. 打开 `https://connect.qq.com`，右上角 **登录**，用 QQ 号扫码/账密登录；
2. 首次登录会自动进入「开发者注册」页，主体类型选 **个人**；
3. 按页面填写（字段以实际页面为准）：**真实姓名、身份证号、手机号（收验证码）、常用邮箱、联系地址**；
4. 上传 **身份证正反面照片**：四角完整、字迹清晰、无反光/无遮挡，不建议加水印遮挡关键信息；
   部分账号会额外要求手持身份证照或人脸核验；
5. 勾选并同意《QQ互联开放平台服务协议》，提交 → 等审核。

> ⚠️ **登录用的 QQ 号一旦注册就不能更换**（官方 wiki 明确提示）。建议用一个长期可控的 QQ，
> 不要用临时小号；后续所有应用维护都用这个号。

## 4. 创建网站应用（关键字段照着填）

入口：`https://connect.qq.com/manage.html#/` → **创建应用** → 选择 **网站应用**

| 字段 | 建议填法 | 说明 |
| --- | --- | --- |
| 应用名称 | `必得题库` | 与备案网站名称一致最稳；不要出现「官方/中国/国家/政府」 |
| 应用分类 | 教育 → 教育信息服务 / 在线教育（按实际可选） | 分类要和网站内容一致 |
| 网站地址 | `https://igoiget.com` | 必须能正常打开、有内容 |
| 回调地址 | `https://igoiget.com/auth/qq/callback` | 只能是**已备案域名**下的 https 地址；不能用 IP、localhost、端口、`#` |
| 网站备案号 | `宁ICP备2026004293号` | 与工信部查询结果完全一致 |
| 应用图标 | PNG/JPG，≥100×100（正方形） | 用站点 logo，别用二维码/截图 |
| 应用简介 | 「公务员、事业单位备考在线题库与结构化面试练习平台」 | 一句话说清业务，不要堆关键词 |
| 联系邮箱/手机 | 与实名一致 | 审核会用来联系你 |

提交后状态变为「审核中」，通过后 `appid`（= `oauth_consumer_key`）、`appkey`（= `oauth_consumer_secret`）就位。

## 5. 周末去提交要带的材料清单

**身份材料**
- [ ] 身份证原件（拍正反面，光线均匀、四角完整）
- [ ] 本人实名手机号（收验证码，且与阿里云/微信小程序尽量同一个，便于主体一致）
- [ ] 常用邮箱（能收审核通知）
- [ ] 长期使用的 QQ 号（注册后不可换绑）

**网站材料**
- [ ] 域名：`igoiget.com`（已备案）
- [ ] 备案号：`宁ICP备2026004293号`
- [ ] 备案信息截图：`https://beian.miit.gov.cn` 查询结果整页截图（含主办单位、网站名称、备案号）
- [ ] 网站首页截图：PC 端 + 375px 移动端各一张（能看清页头、题库入口、页脚备案号）

- [ ] 应用图标素材（100×100 / 512×512 各一份）

**可选（能显著提高一次过审率）**

- [ ] 说明文档：登录场景怎么写（「用户使用 QQ 登录后同步错题与答题历史」）

## 6. 审核最容易卡住的 7 条

1. **网站打不开 / 证书报错**：提交前用手机 4G 打开 `https://igoiget.com` 和 `https://www.igoiget.com` 各一次；
2. **无备案号展示**：页脚必须能看到 `宁ICP备2026004293号` 并链接工信部（我们已有）；
3. **缺隐私政策**：登录类应用几乎必查，弹窗占位不算「可访问 URL」；
4. **回调地址不合规**：带端口、带 `#`、用 IP、用未备案的其他域名，全部驳回；
5. **应用名称含违规词**：包括「官方」「中国」「国家」「政府」「认证」等；
6. **网站内容与分类不符**：分类写「教育」但站点只有一页介绍，会被判空壳；
7. **同一主体重复提交**：改名重提容易排队更久，先按驳回意见改。

## 7. 通过之后（代码侧怎么接，先记账不做）

- `appkey` **只能放服务端**：本机 `.env`、服务器 `/etc/bideti/bideti.env`，不进 Git；
- 服务端新增 `/api/auth/qq/authorize`、`/api/auth/qq/callback`（`server.ts` 与 `netlify/functions/api.ts` 两端共用 `shared/` 逻辑）；
- 数据表建议 `user_oauth(provider, openid, unionid, user_id, created_at)`，`UNIQUE(provider, openid)`，
  RLS 只允许服务端（`service_role`）写；
- 前端：`AuthModal` 顶部加「QQ 登录」按钮，跳转授权页，回调后拿自定义 token 换 Supabase 会话；
- 官方接口（自研接入，不用 SDK）：
  - 授权页 `https://graph.qq.com/oauth2.0/authorize`
  - 换 token `https://graph.qq.com/oauth2.0/token`
  - 取 openid `https://graph.qq.com/oauth2.0/me`
  - 取资料 `https://graph.qq.com/user/get_user_info`（需 `get_user_info` 权限）

## 8. 常见问题

- **个人能不能申请网站应用？** 能，个人开发者可创建网站应用；但部分能力（如某些分享/支付）只对企业开放，纯登录不受影响。
- **审核要多久？** 官方没有承诺时限，实测多在 1–3 个工作日；被驳回会给出原因，按原因改后重新提交。
- **必须用备案域名吗？** 必须。回调地址域名要在你名下的已备案网站上。
- **能不能先用 localhost 联调？** 审核阶段不行；通过后可在测试应用里加临时回调，但线上回调必须是备案域名。
