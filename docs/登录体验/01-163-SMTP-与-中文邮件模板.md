# 01 · 163 邮箱 SMTP + 中文邮件模板（今天做完）

> 目标：用户在 `igoiget.com` 点「发送验证码」后，**10 分钟内**收到一封**全中文**的必得题库邮件，填 6 位码即可登录。
> 现状：Supabase 自带邮件服务只能发给「项目团队成员」，且限 **2 封/小时**，线上根本不可用，所以必须换 163。

## 一、163 侧：拿到「授权码」（不是登录密码）

1. 浏览器登录 `https://mail.163.com`（账号以 `deploy/04-certbot.sh` 里登记的 `luoweilw@163.com` 为准）；
2. 顶部 **设置 → POP3/SMTP/IMAP**；
3. 开启 **SMTP 服务**（会要求手机短信 / 将军令验证）；
   开启后 163 会**强制**所有第三方客户端用「授权密码」登录，登录密码不再可用；
4. 点 **新增授权密码**，按提示验证后得到一串 **16 位字母数字**（形如 `ABCDEFGHIJKLMNOP`）；
5. **立刻复制保存**——该串只完整显示一次，丢了只能删掉重建。

> 注意：163 免费个人邮箱有**发信频率与日发信量上限**（超限时 SMTP 直接返回 `550` / `554` 类错误）。
> 试点阶段够用；用户量上来后要换企业邮箱或专业邮件服务（阿里云邮件推送 / SendGrid 等），届时只改 Supabase 一处。

## 二、Supabase 侧：自定义 SMTP

路径：Supabase 控制台 → 项目 → **Authentication → Emails → SMTP Settings**（旧界面在 **Project Settings → Auth**）

| 字段 | 值 | 说明 |
| --- | --- | --- |
| Enable custom SMTP | 开 | 不开的话邮件只能发给团队成员 |
| Host | `smtp.163.com` | |
| Port | `465` | SSL 直连；若 465 被占用可试 `587`（STARTTLS） |
| Username | `luoweilw@163.com` | 必须填**完整邮箱** |
| Password | 上一步的 **16 位授权码** | 不是登录密码 |
| Sender email | `luoweilw@163.com` | **必须与 Username 完全一致**，否则 163 报 `553` |
| Sender name | `必得题库` | 收件人看到的发件人 |
| Minimum interval per user | `60` 秒 | 与前端 60s 冷却一致，防连点 |

同一页下方还有邮件频率相关设置，另需在 **Authentication → Rate Limits** 里把
**Email OTP Expiration** 改成 `600`（默认 3600）。`AuthModal` 文案写的是「10 分钟内有效」，不改会自相矛盾。

配完点 **Save**，再用页面上的 **Send test email** 发一封到自己的另一个邮箱验证。

## 三、模板改成中文（5 个文件已备好）

模板在 **Authentication → Emails**，一个模板一条：

| 控制台模板 | 用哪个文件 | 建议主题 |
| --- | --- | --- |
| Magic Link | `email-templates/magic-link.html` | `必得题库 · 登录验证码 {{ .Token }}` |
| Confirm signup | `email-templates/confirm-signup.html` | `必得题库 · 完成注册（验证码 {{ .Token }}）` |
| Reset Password | `email-templates/reset-password.html` | `必得题库 · 重置密码` |
| Change Email Address | `email-templates/change-email.html` | `必得题库 · 确认更换邮箱` |
| Reauthentication | `email-templates/reauthentication.html` | `必得题库 · 身份验证码 {{ .Token }}` |

**最关键的一条**：关掉 `Confirm email`（见 `04-Supabase-后台核对清单.md` 第 1 节）后，
`signInWithOtp` 走的是 **Magic Link** 模板，里面**必须**有 `{{ .Token }}`，
否则用户收到的邮件只有链接、没有 6 位码，前端「验证码登录」直接废掉。
`Confirm email` 开着时，新邮箱的 `signInWithOtp` 走 **Confirm signup** 模板（英文+链接），
这就是"改了 Magic Link 没效果"的原因。变量说明见 `email-templates/README.md`。

## 四、验收（4 步，5 分钟内可跑完）

1. 打开 `https://igoiget.com` → 点右上角登录 → 输入**一个非团队成员的真实邮箱** → 发送验证码；
2. 页脚出现「验证码已发送，请查收邮箱（含垃圾箱），10 分钟内有效。」；
3. 邮箱收到的应是**中文**邮件，包含 6 位数字 + 一个「一键登录」按钮；
4. 填 6 位码 → 登录成功，额度条从「游客 10 题」变成「50 题」。

## 五、常见错误对照

| 现象 / 报错 | 原因 | 处理 |
| --- | --- | --- |
| `Email address not authorized` | 没开自定义 SMTP | 回到第二节 |
| `535 Authentication failed` | 授权码错、或 163 侧没开 SMTP 服务 | 重新生成授权密码 |
| `553 Mail from must equal authorized user` | Sender email ≠ Username | 改成同一个 163 地址 |
| `550` / `554` + 中文提示「发送频率过高」 | 163 个人邮箱限频 | 等几分钟；或换发信服务 |
| `email rate limit exceeded` | Supabase 侧限流 | 降低测试频率，或调 Rate Limits |
| 收不到信，但控制台显示已发送 | 进了垃圾箱 / 163 拦截 | 提醒用户查垃圾箱；给域名配 SPF（后续可选，见下） |
| 前端提示「验证码错误或已过期」 | 模板里没放 `{{ .Token }}`，或超过有效期 | 改模板；把 Expiration 设为 600 |

**关于送达率（可选加分项）**：163 代发时 `From` 是 163 地址，域名 `igoiget.com` 不参与签名，
所以不需要配 SPF/DKIM；如果以后换成「自有域名发信」，才需要在 DNS 加 SPF、DKIM、DMARC。
